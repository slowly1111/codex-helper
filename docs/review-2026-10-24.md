# 2026-10-24 对抗性审查与优化

本轮覆盖额度读取、重置消息同步、通知去重、缓存、倒计时及小组件数据入口。软件自动更新与自动重试继续关闭，OpenAI 可执行文件的签名要求保持不变。

| 已发现问题 | 修复与验证 |
| --- | --- |
| 重置 API 原先完整接收响应后才检查体积，异常响应可能占用大量内存 | 改为流式接收，声明长度与实际接收量均限制在 1 MB；超限立即取消，拒绝跳转；模拟无长度分块超大响应验证提前停止 |
| 同步停止后，迟到的请求与通知权限回调仍可能更新状态 | 加入服务代次和会话身份校验，取消旧请求；验证停止后的缓存不写入，以及服务可重新启动 |
| 请求跨越北京时间午夜可能混用两个日期的快照 | 一次同步固定日期，在提交前再次检查；跨日时保留旧缓存并报同步失败 |
| 额度服务无响应时可能持续显示加载，密集刷新也会重复请求 | 初始化与读取均设 20 秒超时，合并并发刷新，限制未换行输出缓冲，清理管道；无法正常终止的本工具子进程在 1 秒后结束 |
| 极大或异常的日期、比例可能触发整数转换崩溃；重复额度 ID 可能干扰列表 | 校验数值、时间戳、周期和小组件缓存，限制缓存读取大小，合并重复 ID；无效值显示不可用，保留上一份有效额度 |
| 来源帖子顺序及相同修订时间可能造成误报或顺序不稳定 | 规范化来源顺序，稳定处理冲突，拒绝同日重复事件 ID，增加旧缓存指纹迁移 |
| macOS 通知缺少已确认消息的具体时间 | 菜单栏与系统通知共用时间说明，显示北京时间、网站推算或来源确认标记；发送期间出现的新消息会继续处理 |

旧缓存首次迁移时，以界面展示的类型、标题、状态、范围与时间判断变化，避免单纯指纹算法变化重报历史消息；之后继续比较来源内容。只有来源正文或链接发生变化、但展示字段未变化的更新，在这一次迁移中不额外弹窗。
