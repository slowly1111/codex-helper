# 菜单栏概览收起修复

## 行为与原因

之前只依赖 `NSPopover.behavior = .transient`，并启用系统动画。没有直接处理窗外鼠标点击。辅助应用可能在弹窗出现时就处于非激活状态，单靠焦点变化不足以覆盖每次窗外点击；这是代码层面的原因分析，未对系统内部延迟作计时测量。

现在在弹窗展示期间同时监听本应用和其他应用的鼠标按下事件，点击弹窗之外立即关闭，关闭动画禁用。原始鼠标事件继续传递，用户点击的页面或按钮照常响应。点击菜单栏锚点交给原来的鼠标抬起切换逻辑，避免关闭后又重新打开。

保留本应用的 Escape 收起操作，并在应用失活、弹窗失去键盘焦点、切换桌面及其他应用激活时清理弹窗。打开主页面和退出也主动关闭。监听安装失败时回退到系统 transient 行为。

所有监听仅在弹窗显示期间存在，关闭、显示失败或控制器销毁时移除。全局监听只接收鼠标按下，不监听其他应用键盘、不保存事件、不新增网络请求。

参考：[Apple Event Monitoring](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)。本地监听覆盖本应用，全局监听覆盖其他应用，事件处理均在主线程完成。

## 验证与边界

2026-10-24 在 macOS 本地完成：

- 优化构建、warnings-as-errors 和应用自检通过。
- 完整安装包 strict/deep 签名校验通过，安装主程序与最终签名构建文件的 SHA-256 一致。
- 使用同一份生产控制器及视图源码构建独立交互校验窗口，实际鼠标点击验证窗外左键、右键、再次点击锚点及跨应用点击均会收起。
- 窗外原按钮同时执行，无需第二次点击；连续打开与收起后没有立即重开。
- Escape 可收起；弹窗内刷新动作完成后仍保持打开。
- 检查显示失败、重复关闭、监听移除、退出和主页面跳转等异常及回归路径。

交互校验窗口使用模拟额度，无账号及网络操作。弹窗内刷新通过辅助功能动作触发，未将其视为真实鼠标事件测试。已安装实际应用的自检和额度读取另外检查通过。未对多显示器、全屏 Spaces 或鼠标中键进行实际交互验证；相关事件与清理路径已检查。
